# 出图设计规范 · 压花玻璃

出图页面（帮助 / 状态 / 关于 / 更新日志）的版式与配色规范。

材质参考是**浴室压花玻璃**：底下有色块透过来、表面有短促的白色鳞片反光。
纹理参数不是凭感觉配的，来自三轮试板 `temp/proto/glass-test{,2,3}.html`，
选定的是第三轮的 **Q 档**（冷色 + 疏密调制）。试板留在仓库里，调参前先看那三张。

真源是代码，不是本文档：

- 颜色与材质分档 `src/modules/render/theme.ts`
- 背景三层 `src/modules/render/components/Layout.tsx` 的 `Backdrop`
- 版式 `components/{Help,Status,About,Changelog}.tsx`

---

## 0. 换掉上一版的理由

上一版是「弥散渐变 + 一层平铺灰度噪点（`baseFrequency 0.3`，opacity .07）」。

噪点解决的是「大片纯渐变显廉价」，但它是**平的** —— 画面仍然读作「一张有噪点的
渐变图」，不是一种材质。压花玻璃的质感来自两件事，缺一不可：

|      | 手段                 | 它负责什么         |
| ---- | -------------------- | ------------------ |
| 折射 | 底色被玻璃的起伏推歪 | 「看不清后面」     |
| 高光 | 朝光的坡面反白       | 那些短促的白色鳞片 |

**折射这一层最终没有落地**，理由见 §1 —— 真实背景的色斑已经被 `blur 144~184px`
糊过，再叠位移看不出差别，白付一次昂贵的 `feDisplacementMap`。

## 1. 背景三层

顺序不能换，`Backdrop` 里从下往上：

### ① 弥散渐变（五团色斑）

五团而不是三团：三团各自成形、能数出「三个光球」；五团尺寸位置错开后互相咬合，
边缘在 blur 下融掉，出来才是整片晕染。`blur 144~184px`，团边落在画布外。

**色斑必须够饱和** —— 这是从上一版改过来最关键的一处。高光鳞片靠调制底色的
明暗才显出起伏；底色几乎没有色差时，鳞片只是浮在白纸上的白点，读作「有纹理的纸」。
上一版那五团是接近白的粉彩（`#c7dcf4` 这类），alpha 拉到 .62 也只是把底往某个
色相推一点点。现在换成真饱和色，alpha 反而降到 .18~.34。

### ② 压花高光（`filter#gl`）

```
feTurbulence  type=turbulence  baseFrequency=0.1  numOctaves=2  seed=9
feSpecularLighting  surfaceScale=4.4  specularConstant=1.5  specularExponent=15
feDistantLight  azimuth=228  elevation=54
feComposite  in=s in2=s operator=in     ← 只留高光自己的 alpha，否则带一层黑底
```

- `type=turbulence` 而不是 `fractalNoise`：前者的短促笔画才像鳞片
- **尺度是关键**。第一轮试板用 `bf 0.3`，周期只有 3px，渲出来是砂纸不是压花。
  参考图的起伏周期在 10~30px，对应 `bf 0.1`（周期约 10px）

### ③ 疏密调制（`mask#gmask`）

一张大尺度噪声（`bf 0.008`，周期约 125px）当遮罩，`feColorMatrix` 把亮度搬进
alpha：亮处留鳞片、暗处吃掉。**没有这层就是磨砂玻璃** —— 均匀铺满的鳞片是另一种
材质，参考图的鳞片有疏有密。

### mask 必须和它的使用者在同一个 `<svg>` 里

落地时踩过：DOM、filter、mask 全都在，屏幕上什么都没有。

`filter` 的 region 相对**被应用元素**算，所以放在 `<svg width=0 height=0>` 里跨
引用没问题。`mask` 不一样 —— mask 内容里的 `100%` 相对**它所在的 svg 视口**，
放进 0×0 的 svg 就等于 0，整个高光层被遮光遮掉。

同理 `rect` 用绝对高度（`1440×6000`）而不是 `100%`：页面高度由内容决定，
svg 拿不到确定参照。

## 2. 高光强度必须按主题分档

`Palette.gloss = { opacity, blend }`，深浅两套取值完全不同。这不是微调，是**必须**：

|      | blend     | opacity | 为什么                                                   |
| ---- | --------- | ------- | -------------------------------------------------------- |
| 浅色 | `screen`  | `.85`   | 白鳞片压在浅色渐变上就是玻璃反光。试过 .62，鳞片明显发闷 |
| 深色 | `overlay` | `.06`   | `screen` 对深色几乎等于直接叠纯白                        |

深色用 `screen` 的后果实测过一次：**一屏雪花，正文完全不可读**。
`overlay` 在暗部是 `2·base·blend`，提亮量与底色成正比，所以深色区域只被轻微擦亮，
读起来像烟熏玻璃。

> 这个坑对比度测试抓不到。`test/contrast.mjs` 算的是 `foreground` 对 `bg` 这个
> **平底**，不算 glow 与高光层叠上去之后的实际像素。改高光参数后必须看截图，
> 或者跑 `test/inkprobe.mjs` —— 它把内容层隐藏、只截背景，逐像素统计亮度分位，
> 再拿真实调色板里的 ink 值去比。两套的最坏情况在**相反那一端**：
>
> |      | p1（最暗） | p50   | p99（最亮） | 谁是最坏情况          |
> | ---- | ---------- | ----- | ----------- | --------------------- |
> | 浅色 | L=0.718    | 0.805 | 0.972       | p1 —— 深字怕背景变暗  |
> | 深色 | L=0.009    | 0.022 | 0.042       | p99 —— 浅字怕背景变亮 |
>
> 这就是 `muted` 两套都被重配过的原因（`#5b6577`→`#4c5666`、`#8b95a8`→`#9ba5b6`）：
> 它们在平底上一直「达标」，在极端区域各差 0.2 和 0.5。

`Backdrop` 因此要读调色板 —— `Page` 里那个 `palette` 曾经是 `_palette`（有意不用）。

## 3. 颜色

浅色走冷色（试板 Q 档），与前景的蓝紫青同族：

| 用途 | 值                                                                                 |
| ---- | ---------------------------------------------------------------------------------- |
| 色斑 | `#5b93de` 天蓝 · `#838bcc` 蓝紫 · `#2b9ade` 亮蓝 · `#7cb238` 淡绿 · `#bfc9d4` 银灰 |
| 强调 | `primary #2563eb` · `secondary #7c3aed` · `accent #0f766e`                         |

**为什么不用绿色那张试板**：它更像玻璃，但整页强调色是蓝 / 紫 / 青，还有 `spectrum`
那组深蓝紫的大数字 —— 绿底一上来全成补色对撞。而这些色不能顺手改：`rotate` 必须与
`primary/secondary/accent` 同值（`contrast.mjs` 有一致性断言），改它们要连状态点、
链接、成功 / 警告一起重配。

淡绿那团压到最低 `.18`：它是唯一的暖偏色，浓了在蓝底上显脏。

色斑 alpha 的上限由正文定：斑越浓，落在斑上那部分字与 `contrast.mjs` 算出来的值
偏离越大。`.34` 是当前上限。

## 4. 字体

**只有两族**。sans（正文与标题）+ mono（版本号、时间、命令、计数）。

原型里曾有第三族 Palatino 衬线用在英文微标签上，用
`CSS.getPlatformFontsForNode` 查过确实命中了 —— 一个书卷气的正文衬线压在几何无衬线
的中文和等宽数字之间就是第三种语气，这是「字体看着怪」的主要来源。这些微标签本来
就该用 `font-mono + uppercase + tracking`（`Footer` 一直是这么写的）。

### `MONO_STACK` 尾部必须挂中文回退

同一次探测发现示例行 `#早柚添加连接 ws://127.0.0.1:8765/ws` 命中的是：

```
JetBrains Mono×26 | NSimSun×6
```

拉丁走 JetBrains Mono，**中文掉到 NSimSun** —— 点阵时代的宋体等宽，笔画又细又硬，
和 JetBrains Mono 的拉丁差着一个年代，同一行里混着看最刺眼。补上回退后变成
`PingFang SC×6 | JetBrains Mono×26`。

代价是中文在 mono 里不再等宽。可以接受：需要对齐的全是数字与拉丁，那部分照旧。

> 两个字体栈在 `theme.ts` 与 `styles/tailwind.css` 的 `@theme` 里各有一份拷贝。
> 颜色靠 `var()` 只留一处真源，字体不行 —— `@theme` 的值要编译期确定。**改一边
> 记得改另一边**，不一致的表现是「用 `font-mono` 的元素和用 `MONO_STACK` 的元素
> 字体不一样」，只在少数地方看得出来。

## 5. 内容区不加框

条目、分组、参数表**都没有边框**，靠留白与缩进分隔。

### 「去掉 border」不等于无框

原型上走过一次弯路：border 删了，但半透明矩形压在纹理上，**四条边照样是清晰轮廓**，
照样和背景抢视野。真要消掉轮廓得两步：左右负 margin 溢出到画布边缘，上下用
`mask-image` 渐变淡出。

那一版最后**整体否掉了** —— 半透明底板无论怎么处理边缘，本质都是「换个手段把背景
挡住」，而背景是这版设计的主体。现在文字直接压在玻璃上。

### 直接压纹理要解决的问题

高频鳞片会和字的笔画抢像素：笔画宽约 1.5px，鳞片也是 1~2px，频率太近，看着发毛。
靠三件事把字立住，缺一不可：

1. 字号整体上调，笔画变粗，与鳞片的频率拉开
2. 高光层不做全局压制，靠 §1③ 的疏密调制让大部分文字落在鳞片稀疏处
3. 深色那套把 opacity 压到 `.06`（见 §2）

### 图标一律用 lucide，不手绘

`Icons.tsx` 按语义名（`"status"` / `"changelog"`）映射到 `lucide-react` 组件，
`commands.ts` 只写语义名。换图标只动那张表。

**lucide 是描边图标**：`fill` 必须显式设成 `none`，否则浏览器按 SVG 默认的
`fill:black` 把每条开放路径首尾相连再填黑，图标糊成一团墨块。
`stroke-width 2` + round 连接是 lucide 的规范值，改了就和它的视觉重量不一致。

## 6. 页脚

四块**居中**排（`justify-content:center` + `gap 32px`），不是两端对齐：

```
[图标80] PLUGIN / 插件名   ✓STABLE / 版本号   │3×56   [图标80] POWER BY / 框架名 版本
                    时间戳  ·  MASTER 标记的指令仅主人可用
```

原型里用过 `flex:1` 的 spacer 把两半推到画布左右两端，中间空一大片 —— 那读起来是
三个孤岛而不是一行水印。

两张 logo 的**缩放方式不同**，这不是笔误：`logo.webp` 的字形只占画幅 70.7%，
img 溢出框 `112%` 把留白顶出去；`frame-logo.webp` 是满幅不透明图，内缩 8px。
这样两边字形都是约 63px。统一按同一种缩放，早柚那个会小三分之一。

一行放不下时靠 `--fs` 等比缩字号（`Footer` 里按 `textWidth` 预算），不换行 ——
换行会把「插件 × 框架」的并列关系拆断。

## 7. 体积

出图是 JPEG（quality 88），这层锐利噪声直接换算成体积：

|            | 上一版（平铺噪点） | 现在（压花玻璃） |
| ---------- | ------------------ | ---------------- |
| help-dark  | 495 KB             | **908 KB**       |
| help-light | 396 KB             | **1024 KB**      |

试过三档省体积的改法，**全部否掉**：

```
bf 0.1→0.05 + blur 0.85   646 KB   鳞片被拉成脑珊瑚那样的虫状纹
bf 0.1→0.07 + blur 0.55   900 KB   介于两者之间，仍偏糊
numOctaves 2→1             ——      细节层没了，只剩一层大波浪
```

blur 与降频率省下的体积，直接换掉了这层要的东西。**压花玻璃的鳞片必须是锐的**，
糊了就是磨砂玻璃。所以这里选择付体积。

功能上没有阈值问题：`render/index.ts` 只有固定的 `quality: 88`，没有按体积二次
压缩的逻辑。

## 8. 硬约束（改任何一条前先读）

1. **改高光参数后必须看截图，或跑 `test/inkprobe.mjs`。** `contrast.mjs` 只算平底，
   抓不到高光层咬花正文。深色那次雪花事故就是这么漏过去的。
2. **`gloss` 深浅必须分档。** 深色用 `screen` 会得到一屏雪花。
3. **mask 与它的使用者同一个 `<svg>`。** 跨 svg 引用 mask 会静默失效。
4. **`rotate` 与 `primary/secondary/accent` 同值。** `contrast.mjs` 有断言。
5. **字体栈两处拷贝同步改。** `theme.ts` 与 `tailwind.css` 的 `@theme`。
6. **lucide 图标 `fill:none`。** 否则糊成墨块。
7. **色斑 alpha 上限 `.34`。** 再浓会让正文与算出来的对比度偏离过大。
8. 改完跑 `pnpm build && pnpm test`，再 `node --import tsx test/preview.mjs`
   看四个页面的深浅两套。`test/shot.mjs` 出 JPEG 顺便核体积，`test/inkprobe.mjs`
   核正文在真实像素上的对比度。

> `test/` 在 `.gitignore` 里（CI 克隆不到，所以流水线没有测试步骤）。上面这几个
> 脚本都只在本地跑。
