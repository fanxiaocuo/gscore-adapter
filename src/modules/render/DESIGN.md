# 出图设计规范 · 弥散渐变

出图页面（帮助 / 状态 / 关于 / 更新日志）的版式与配色规范。

材质是**纯弥散渐变**：五团大色斑互相咬合铺满整幅，上面压一层极低频的絮状调制与一道很轻的
暗角。中间那版**压花玻璃**（表面短促的白色鳞片）已经整个拿掉，理由见 §0 —— `filter#gl`、
`mask#gmask`、调色板里的 `gloss` 字段都不在了，凡讲鳞片 / 高光 / `feSpecularLighting` 的
说法都不再有对应代码。试板 `temp/proto/glass-test{,2,3}.html` 仍留在仓库里，但那是压花
时代的东西，不再是现在这套的依据。

真源是代码，不是本文档：

- 颜色与色斑分档 `src/modules/render/theme.ts`
- 背景各层 `src/modules/render/components/Layout.tsx` 的 `Backdrop`
- 版式 `components/{Help,Status,About,Changelog}.tsx`

## 0. 换掉上一版的理由

这套背景到现在是第三代：

| 代         | 材质                                                 | 为什么被换掉                                   |
| ---------- | ---------------------------------------------------- | ---------------------------------------------- |
| 一         | 弥散渐变 + 一层平铺灰度噪点（`bf 0.3`、opacity .07） | 噪点是**平的**，画面读作「一张有噪点的渐变图」 |
| 二         | 压花玻璃（`feTurbulence` + `feSpecularLighting`）    | 见下面三条                                     |
| 三（当前） | 纯弥散渐变 + 极低频絮状调制 + 暗角                   | —                                              |

压花玻璃确实解决了第一代那个「平」，但它自己带来三个问题，三条一起才够翻案：

1. **体积。** `COOL` 完整一张 2409 KB，关掉高光层只剩 527 KB —— 中间调加高频锐噪正好是
   JPEG 的 DCT 最压不动的组合，那一层鳞片一个人吃掉七八成体积（数字见 §7）。
2. **和字抢像素。** 鳞片周期 1~2px，中文笔画宽约 1.5px，两个频率贴在一起，小字看着发毛。
   当时是靠「字号整体上调 + 疏密调制让文字落在鳞片稀疏处」压着的 —— 那是在和材质对着干。
3. **不好看。** 最直接的一条：满幅规则鳞片压在信息密集的版面上，观感被判为不好看。
   前两条是代价，这条是它没换来东西。

**这不是退回第一代。** 第一代的毛病是「高频的平噪点」，而现在这层絮状调制周期约 110px
（旧鳞片约 10px），差一个数量级 —— 它不是纹理，肉眼不成形，只负责让渐变不发板、不出带阶。
「不显廉价」这件事改由三件事撑：色斑的**色相跨度**、絮状调制、暗角（§1）。

> 压花那版本来还设计了第三层「折射」（`feDisplacementMap` 把底色推歪），**始终没有落地**：
> 真实背景的色斑本身就是极平滑的大尺度渐变，再叠位移看不出差别，白付一次昂贵的滤镜。
> 现在连高光都没了，这条更不必再试。

## 1. 背景各层

顺序不能换，`Backdrop` 里从下往上：弥散渐变 → 絮状调制 → 暗角，再加上气氛大字、
两块角落装饰与左下那团柔光。

### ① 弥散渐变（五团色斑）

五团而不是三团：三团各自成形、能数出「三个光球」；五团尺寸位置错开后互相咬合，
出来才是整片晕染。半径普遍放大到超出画布，团边落在画布外。

**不挂 CSS 模糊。** 曾经每团带 144~184px 的 blur，去掉之后帮助页截图从 5090ms
掉到 1530ms（整张图七成耗时），而逐像素比对平均差 1.93/255、p99 差 8，肉眼分不出
—— 边本来就是渐变自己在 66~74% 处收干吃掉的，模糊一个已经平滑的函数几乎等于没做。
配套试过的两条也记在 `Layout.tsx` 里：降采样后 `scale()` 放回去（画面一样、一点没省，
Chromium 按最终设备尺度光栅化）、`will-change` 强行提升成合成层（4299ms，仍不如不模糊）。

**配色目标改了。** 压花时代要求色斑「够饱和」，理由是鳞片靠调制底色明暗才显出起伏，
底色无色差时鳞片只是浮在白纸上的白点。现在没有鳞片，目标换成让整片场走过一段色相，
靠色相跨度而不是浓度让画面不显廉价。手段也因此反过来：**alpha 整体压低**，
COOL 依次 .26 / .24 / .20 / .20 / .18，LIGHT 依次 .22 / .21 / .17 / .17 / .22；
同时把原本五团全是蓝族（天蓝 / 蓝紫 / 亮蓝 / 淡绿 / 银灰）的配色推开色相跨度 ——
蓝紫推成真紫、淡绿换成暖玫 `rgba(226,158,126,…)`，银灰留作粘合压在最不起眼的位置，
冷场里有一处暖，视线才有落点。

注意：暖玫不能压太低。第一版给了 .13，在银灰底上被整个吃掉，整幅仍是一片蓝灰 ——
「唯一的暖色浓了会显脏」是压花时代的经验（那时它要和鳞片抢像素），现在它反而是唯一
能让画面不单调的东西，COOL 抬到 .20、LIGHT 抬到 .17，才走得出来。

### ② 絮状调制（`filter#fl`）

```
feTurbulence  type=fractalNoise  baseFrequency=0.009  numOctaves=3  seed=17
feColorMatrix  把亮度搬进 alpha：斜率 .16，负偏置 -.04
整层  opacity-[.5]  mix-blend-mode: soft-light
```

这不是纹理，是**频率治理**。旧的那层（`bf 0.1`，周期约 10px，`feSpecularLighting`）
与中文笔画宽度（约 1.5px）频率太近，渲出来是雪花；而 JPEG 的 DCT 最压不动的正好是
中间调加高频锐噪，所以它一个人吃掉七八成体积。

现在只留 `0.009`（周期约 110px）的 `fractalNoise`，不加镜面光照。出来是大块柔和的
明暗起伏，肉眼不成形、不与字争，只把纯渐变那种塑料感压掉。`feColorMatrix` 把亮度搬
进 alpha 并压到很低（斜率 0.16 + 负偏置），于是只有噪声的亮处留下一点提亮，暗处直接
透明 —— 永远只提亮、不压暗，不会吃掉正文对比度。低频对 DCT 友好，几乎不涨体积。

注意：opacity 别往上抬。这层的作用是「让人说不出哪里不平」，一旦看得出颗粒就成了
另一个纹理问题。

注意：`rect` 用绝对高度（`1440×6000`）而不是 `100%`：页面高度由内容决定，
svg 拿不到确定参照。

### ③ 暗角

```
opacity-[.085]  background: radial-gradient(ellipse at 50% 40%, transparent 42%, var(--fg) 100%)
```

五团色斑铺满整幅之后四角最容易发飘 —— 尤其近白的 `LIGHT`，边缘几乎与页面外的白融
在一起，画面没有边。一道很轻的径向暗角给它收个口。

用 `--fg` 而不是写死黑：`COOL` 的前景是 `#0f1720`（偏蓝），纯黑压在银灰底上会显脏。

注意：第一版给的是 58% + `.055`，四角根本没收住 —— 起点太靠外、浓度也太淡。
现在 42% 起收、`.085` 收尾，画面才有边。再往内会压到统计条那一带的正文，
`inkprobe` 会先报出来。

### 左下柔光

```
bottom-[-220px]  left-[-180px]  h-[720px]  w-[860px]  opacity-[.5]
background: radial-gradient(ellipse at 46% 54%, var(--glow-2) 0%, transparent 70%)
```

左下角那块 45° `repeating-linear-gradient` 斜纹已替换成一团柔光。原因：斜纹是压花
时代的遗物，那时满屏鳞片，一块 5px 周期的规则纹理混在里面看不出来；背景一干净，
它就成了整幅唯一一块「机器画的几何」，而且只在左下角、右边没有对称物，读作画错了
地方。换成同色系的辉光，仍然给左下角一点分量，但它与五团色斑是同一种语言。

### 压花时代留下的一条坑：mask 必须和它的使用者在同一个 `<svg>` 里

现在背景层里已经没有 `mask`（`mask#gmask` 随疏密调制一起删了），这条记在这里是因为
哪天再引入 mask 会原样再踩一次：当时 DOM、filter、mask 全都在，屏幕上什么都没有。

`filter` 的 region 相对**被应用元素**算，所以放在 `<svg width=0 height=0>` 里跨
引用没问题 —— 现在的 `filter#fl` 就是直接写在使用它的那个 svg 里。`mask` 不一样：
mask 内容里的 `100%` 相对**它所在的 svg 视口**，放进 0×0 的 svg 就等于 0，
整层会被遮光遮掉。

## 2. 两套都是亮底 —— 曾经的深色去哪了

现在只有 `LIGHT`（白天，近白 `#f4f6fb`）与 `COOL`（夜里，银灰 `#c6d0da`）。
`COOL` 原名 `DARK`，`bg` 是 `#0a0d14` 的真深色。

当初换掉它的理由是压花的：「深底上 `screen` 高光是一屏雪花」。**那条理由已经作废** ——
高光层没了，深底上不会再有雪花。但亮底这条约束保留，理由换成下面两条：

|                          | 深底上会怎样                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 色斑是半透明叠色         | 在近黑上几乎不产生色差，弥散层等于白铺 —— 而它现在是画面的**唯一**主体，下面再没有纹理兜底                              |
| 全套颜色照亮基色实测配过 | 六个角色色、`muted`、`spectrum` 都是对 `#f4f6fb` / `#c6d0da` 量出来的（下面两小节），换深底等于这批取值全部作废、要重配 |

第一条比压花时代更硬：那时候色斑透不出来还有满屏鳞片撑着画面，现在它下面什么都没有。
暗角同理 —— 它靠把边缘压暗来收口（`--fg` 铺到 100%），深底上无从压。

|         | bg        | glow alpha | 气质         |
| ------- | --------- | ---------- | ------------ |
| `LIGHT` | `#f4f6fb` | `.17~.22`  | 大太阳下的窗 |
| `COOL`  | `#c6d0da` | `.18~.26`  | 阴天的窗     |

**代价说清楚**：不再有夜间护眼的深色出图。取舍理由是出图是发到聊天里的静态图片，
不是长时间盯着的界面；而两套同材质能让版式在一天里保持同一个语言。

### 银灰底为什么停在 `#c6d0da`

再往下一档（`#bfc9d4`）前景那批彩色角色色集体掉出 3.5:1，连深化一档都救不回来：
实测 `primary` 3.08 / `success` 2.99 / `danger` 2.88。

`#c6d0da` 配深化一档的角色色（`#1d4ed8` / `#6d28d9` / `#115e59` / `#166534` /
`#92400e` / `#b91c1c`）全部达标，是「够沉」与「彩色还能用」的交点。

> 改任一套的角色色时看另一套：`COOL` 的六个彩色是照 `LIGHT` 各深化一档配的。
> `test/contrast.mjs` 守住这件事。

### 正文墨色要按真实像素配，不是按平底

`test/contrast.mjs` 算的是 `foreground` 对 `bg` 这个**平底**，不算色斑与絮状调制
叠上去之后的实际像素。跑 `test/inkprobe.mjs` —— 它把内容层隐藏、只截背景，逐像素
统计亮度分位，再拿真实调色板里的 ink 值去比：

|         | p1（最暗） | p50    | p99（最亮） | `foreground` 最坏    | `muted` 最坏        |
| ------- | ---------- | ------ | ----------- | -------------------- | ------------------- |
| `LIGHT` | L=0.7051   | 0.8054 | 0.8796      | 12.76:1（`#101828`） | 5.34:1（`#4c5666`） |
| `COOL`  | L=0.4985   | 0.5737 | 0.6145      | 9.43:1（`#0f1720`）  | 4.92:1（`#3d4754`） |

两套都是深字压亮底，所以最坏情况都在**最暗**那一端（色斑最浓处）。
`muted` 就是这么被重配的：`#5b6577` 在平底上一直显示达标，在最暗区域只有 4.30:1。

删掉高光层之后这批分位整体收窄：`screen` 只提亮，删掉它最亮端就掉下来（`COOL` 的 p99
从压花时代的 0.928 掉到 0.6145）。**最暗那一端也就没有了 screen 的兜底**，`COOL` 的
`muted` 只剩 4.92:1（对正文的 4.5 只有 0.42 余量）—— 这是色斑 alpha 必须跟着压低的
直接原因（§1①），也是「改色斑 / 暗角 / `filter#fl` 之后必须跑 inkprobe」这条约束的
由来（§8）。

> `inkprobe` 里那个「最坏情况」取的是两端的 `min`，不按主题名猜。早先写成
> `mode === "light" ? 最暗 : 最亮`，`DARK` 变成亮底之后就取错了那一端
> （当时报 16.80:1 而真实最坏是 9.45:1，那批是压花时代的数字）。

`Backdrop` 因此要读调色板 —— `Page` 里那个 `palette` 曾经是 `_palette`（有意不用）。

## 3. 颜色

两套共用一组色斑色相 —— 主干是与前景同族的蓝紫青，外加一团暖玫作落点：

| 用途            | 值                                                                               |
| --------------- | -------------------------------------------------------------------------------- |
| 色斑            | `#5b93de` 天蓝 · `#8a7fd0` 紫 · `#2b9ade` 亮蓝 · `#e29e7e` 暖玫 · `#bfc9d4` 银灰 |
| 强调（`LIGHT`） | `#2563eb` · `#7c3aed` · `#0f766e`                                                |
| 强调（`COOL`）  | `#1d4ed8` · `#6d28d9` · `#115e59`（各深一档，配银灰底）                          |

色斑的 **alpha 两套不同**，但两套都比压花时代低一档：`COOL` `.26/.24/.20/.20/.18`、
`LIGHT` `.22/.21/.17/.17/.22`。`COOL` 略高是因为银灰底比近白底暗、同样的 alpha 透出来
的色差更小；`LIGHT` 的银灰那团反而是五团里最实的一个（`.22`），用来把近白的整片场压住
不发飘。

**为什么不整片换成绿**：曾经有一张偏绿的试板，但整页强调色是蓝 / 紫 / 青，还有 `spectrum`
那组深蓝紫的大数字 —— 绿底一上来全成补色对撞。而这些色不能顺手改：`rotate` 必须与
`primary/secondary/accent` 同值（`contrast.mjs` 有一致性断言），改它们要连状态点、
链接、成功 / 警告一起重配。暖玫是这条约束下唯一放进来的暖色：它只是五团里的一团，
不改整片场的基调。

**暖玫不是「压到最低」的那一团。** 「唯一的暖偏色浓了会显脏」是压花时代的经验 —— 那时
它要和满屏鳞片抢像素。现在没有纹理托着，它是唯一能让画面不单调的东西：第一版给 `.13`
在银灰底上被完全吃掉，抬到 `.20`（`COOL`）/ `.17`（`LIGHT`）才走得出来。

色斑 alpha 的上限由正文定：斑越浓，落在斑上那部分字与 `contrast.mjs` 算出来的值
偏离越大 —— 而现在没有高光层的 `screen` 给暗部兜底（§2 末），这条比从前更紧。
当前最浓的一团是 `COOL` `.26` / `LIGHT` `.22`，别抬回压花时代那一档（旧上限 `.34`）。

### 语义色只标异常，不标正常

彩色是稀缺资源，一屏里出现几次就该有几件需要人再看一眼的事：

- **连接卡的账号行**：正常那几行**一个状态字都不给**，只有异常才出文字并拿语义色。
  左边那颗点已按 tone 上色，卡片右上那个大胶囊也已说过「已连接」—— 每行再写一遍是同一句话
  的第三遍，而五个号里四行绿字会把唯一那行橙的「断线重连中」淹掉。这块存在的理由正是让人
  一眼找到出问题的号。中间还经过一版「压成 `muted`」，仍然嫌吵，索引删干净才对。
  注意：判据用 `status` 而不是 `tone` —— `tone` 把 warn / err 之外的都归成一类，
  分不出「已连接」和「已停用」，而后者是该说出来的。
- **设置页改动结果条**：只有失败行的文字给 `danger`，成功行用正文色。三条并排时若全用
  正文色，「指令没生效」就和「已改好」一样重；成功那侧的勾和「= 开启」已经说完了。

## 4. 字体

**只有两族**。sans（正文与标题）+ mono（版本号、时间、命令、计数）。

原型里曾有第三族 Palatino 衬线用在英文微标签上，用
`CSS.getPlatformFontsForNode` 查过确实命中了 —— 一个书卷气的正文衬线压在几何无衬线
的中文和等宽数字之间就是第三种语气，这是「字体看着怪」的主要来源。这些微标签本来
就该用 `font-mono + uppercase + tracking`（`Footer` 一直是这么写的）。

### `MONO_STACK` 尾部必须挂中文回退

同一次探测发现示例行 `#早柚添加连接 ws://127.0.0.1:8765/ws` 命中的是：

```
JetBrains Mono×26 | NSimSun×6
```

拉丁走 JetBrains Mono，**中文掉到 NSimSun** —— 点阵时代的宋体等宽，笔画又细又硬，
和 JetBrains Mono 的拉丁差着一个年代，同一行里混着看最刺眼。补上回退后变成
`PingFang SC×6 | JetBrains Mono×26`。

代价是中文在 mono 里不再等宽。可以接受：需要对齐的全是数字与拉丁，那部分照旧。

> 两个字体栈在 `theme.ts` 与 `styles/tailwind.css` 的 `@theme` 里各有一份拷贝。
> 颜色靠 `var()` 只留一处真源，字体不行 —— `@theme` 的值要编译期确定。**改一边
> 记得改另一边**，不一致的表现是「用 `font-mono` 的元素和用 `MONO_STACK` 的元素
> 字体不一样」，只在少数地方看得出来。

## 5. 内容区不加框

条目、分组、参数表**都没有边框**，靠留白与缩进分隔。

### 「去掉 border」不等于无框

原型上走过一次弯路：border 删了，但半透明矩形压在背景上，**四条边照样是清晰轮廓**，
照样和背景抢视野。真要消掉轮廓得两步：左右负 margin 溢出到画布边缘，上下用
`mask-image` 渐变淡出。

那一版最后**整体否掉了** —— 半透明底板无论怎么处理边缘，本质都是「换个手段把背景
挡住」，而背景是这版设计的主体。现在文字直接压在背景上。

### 分组竖线也去掉了，归组只靠缩进

`Help.tsx` 的分组条目区左侧原来有一条 2px 的分组色贯通竖线（主条目 `47`、子分组 `2e`
两条），**已删除**。理由与本节同一条：竖线也是一种框 —— 一条贯通全组的硬边，和 border
一样在背景上划出轮廓，只是只划了一边。归组要的信息量缩进给得起：主条目 `pl-[34px]`、
子分组 `pl-[30px]`，34 是让条目文字正对标题首字。

### 例外：留卡面的地方一律走液态玻璃

有五处必须留卡面 —— 它们都是「一组并列的条目」，没有卡就退化成一堆浮在背景上的文字，
条与条的归属读不出来：

| 卡面    | 在哪                           | 为什么不能没有卡                       |
| ------- | ------------------------------ | -------------------------------------- |
| `Stats` | 帮助 / 状态 / 更新日志三页顶部 | 四个并列读数，栏的归属                 |
| 连接卡  | 状态 / 连接列表                | 一条连接是名字+地址+账号行+meta 一整组 |
| 提交卡  | 更新日志                       | 一条提交是 hash+标题+时间              |
| 设置行  | 设置 / 配置                    | 开关必须在同一条竖线上对齐             |
| 空态卡  | 连接列表 / 更新日志的空态      | 「这里本该有东西」                     |

原来的做法（白 `.66` 实心面 + 1px 深色发丝边）恰好犯了上面那条：卡一不透，底下那片
背景就被整块盖住，出图里这些卡明显比周围干净、平滑，是整页唯一没有背景的地方。
现在五处共用同一份三件套（`Layout.tsx` 的 `GLASS`）：

| 部位 | 做法                                                             |
| ---- | ---------------------------------------------------------------- |
| 卡面 | 竖向渐变 `.52 → .24` 的白，平均透明度从 `.66` 降到约 `.36`       |
| 边   | 去掉描边，改两条反向 1px 内阴影：左上受光白、右下背光 `--border` |
| 厚度 | 顶部 28px 白色内发光（光在玻璃体内漫射）+ 一层外投影托起卡片     |

**「玻璃边」与「描边」的区别就在方向性**：描边四周同色，玻璃的边随光向一半亮一半暗，
圆角处自然过渡。这也是为什么这里没用 `border` —— 边框四条边只能同一个颜色。

空态卡是唯一的变体（`GLASS_SOFT`）：它那圈虚线是语义标记（「这里本该有东西」，与实线
内容卡区分），不是材质的边。两者叠在同一像素上，左上角就是「虚线的 border 色」紧贴
「受光白线」，读作脏边 —— 所以那里只取面与厚度，边交给虚线本身。

**取值只有 `Layout.tsx` 一份**，五处都引它。曾经是五处各写一遍那串取值，于是 `Stats`
先按本节改成了玻璃、另外四处仍留在实心面上，同一页上下两种材质并存了一段时间。
`classes.test.mjs` 查的是「类有没有定义」，查不出「五处材质不一致」。

透出率（`test/probe-cardface.mjs`，卡面标准差 ÷ 同页裸背景标准差，越高＝底下的东西透得
越多）。**下面这组数字是压花时代量的，透出去的是鳞片；现在透出去的是弥散渐变与低频絮状
颗粒，量纲变了 —— 待重测**：

|        | 改之前    | 改之后（COOL / LIGHT） |
| ------ | --------- | ---------------------- |
| 连接卡 | 36% / 23% | 75% / 69%              |
| 提交卡 | —         | 82% / 82%              |
| 设置行 | —         | 73% / 66%              |
| 空态卡 | —         | 82% / 85%              |

`Stats` 是 83% / 81%，四处都落在它附近 —— 这条「五处彼此接近」才是这张表要守的东西，
它与材质无关：卡面取值只有一份，五处的透出率就该在同一个量级，某一处明显偏低就是有人
在调用处另抄了一串取值。绝对值本身要按新背景重测。

卡上最小的字（23px `muted` 说明、19~21px 等宽）最坏 5.44:1 —— 同样是压花时代的测量，
待重测。当时最亮端有 `screen` 提亮，现在没有（§2 末）。

### 直接压背景要解决的问题

压花时代这里是三条对策：字号整体上调把笔画与鳞片的频率拉开、靠疏密调制让文字落在鳞片
稀疏处、两套基色都用亮的免得白鳞片压在近黑上。**三条都是在和材质对着干**，而材质换掉
之后问题从根上没了 —— 絮状调制周期约 110px，与 1.5px 的中文笔画差一个数量级，不存在
抢像素。

现在只剩两条，都不是补救而是本来就该有的：

1. 字号整体上调 —— 出图在聊天窗口里被缩着看，这条与背景无关，独立成立
2. 背景永远只提亮不压暗（`filter#fl` 的负偏置、暗角压到 `.085`），正文的最坏对比度
   因此可控，`inkprobe` 守住这条（§2 末）

### 控件：状态要有颜色以外的第二个通道

- **开关（`Settings.tsx` 的 `Toggle`）**：96×52 轨道 + 40px 白滑块，**不带文字**。
  开态轨道填 `success` 实色、滑块在右；关态 `${muted}30` 底 + `${muted}47` 描边、
  滑块在左。状态走「填色 + 滑块位置」两个通道，不只靠颜色 —— 截图里没有交互可试，
  两个通道才认得准。
  从前是「一颗点 + 开启/关闭 文字」的胶囊，理由是「iOS 式轨道要 60px，并排放文字会把
  右侧撑到三分之一页宽」。那条推理的前提是文字要留着，而滑块的位置本身就是状态，文字
  是重复的 —— 去掉之后整个控件 96px，比原来带字的胶囊（约 123px）还窄。
  注意：关态轨道用 `muted` 兑出来的灰，不能用 `--inset` —— inset 只比卡面深一档，
  白滑块压上去看不见边。
- **改动结果条（`Settings.tsx` 的 `Result`）**：**GLASS 卡面**（与全页同一种边框）+
  52px 语义色图标方块 + 文字。从前是「语义色描边 + 语义色底 + 6px 左粗边 + 语义色
  文字」，整条红或整条绿 —— 问题不在用了语义色，而在全页只有这三条是彩色描边的块，
  别处一律是同一种玻璃边，它们读起来不像这一页的东西。现在语义色只落在图标方块上
  （与设置行的图标同一种画法），成败仍然一眼分得出。文字的着色规则见 §3 末。
  52px 而不是设置行那个 62px：这几条只有一行字，照抄 62 会让单行文字占到双行设置卡
  一样的高度。

### 同一份东西只枚举一遍

连接卡的账号列表曾经是**两块平行的东西**：一排 bind 头像胶囊，底下再一块 runtime 子行。
两块枚举的是同一份账号，于是一张卡里：

| 重复的东西 | 出现次数 | 在哪                                          |
| ---------- | -------- | --------------------------------------------- |
| 账号号码   | 3        | 胶囊、子行行首、子行路径尾巴                  |
| 心跳       | 3        | 两条子行各一次 + 卡片 meta 一次，值全相同     |
| 收发计数   | 3        | 两条子行 + 卡片那个「聚合值」（就是它们的和） |
| 已连接     | 3        | 卡片胶囊 + 两条子行                           |

调样式治不了这个 —— 根因是结构，不是文案。现在合成一层：**一个账号一行**，自带头像、
昵称、账号、平台、状态点与自己的计数。号码只出现一次，读者也不必在两块之间对着看
「哪个胶囊对应哪条 ws」。

由此派生的四条，改任何一条前先想清楚它替代了什么：

- **路径不画**。自动派生的恒为 `/ws/Yunzai-<账号>`，与同一行左边那个账号重复；而自定义
  路径的连接**恒只派生一条 ws**，根本走不到逐账号这一层。所以曾经那个
  `rt.automatic ? undefined : pathname` 三元里的 else 分支永远走不到，已删。自定义路径
  印在卡片 URL 那一行（`shownUrl` 保留 pathname），信息没丢。
- **心跳提到卡片层，取所有账号里最老的那个**。从前取的是「代表账号」，代码注释自己承认
  那个值是随意的；最老的那个才是该报警的。逐账号不再各印一遍 —— 同一个 ping 周期下
  它们的值几乎一致。
- **聚合收发计数在有账号行时不出**。它只是那几行的和，逐行都印着分量。
- **`exclude: N` 胶囊在账号行标出「已排除」时不出**。那个胶囊当初的理由是「看不出是哪个
  号被挡了」，现在那一行自己写着。但 `exclude` 里的号可能与 `bind` 不相交（写了却挡不到
  任何东西），那时账号行一个「已排除」都不会出现，胶囊是唯一线索，仍然给。

折叠（`RUNTIME_LIMIT` 3 条）的名次因此也换了一套：`foldRank` 把「被 exclude」排在正常
之上、任何异常之下。它不是故障（配置就那么写的），但藏起来就没人看得出 `bind` 与
`exclude` 撞了。

#### 账号块贴合内容，但右侧那组恒占位

两条约束互相牵制，缺一条都会露出来：

**块要 `self-start`。** 它在卡片主信息列（一个 flex 列）里，默认 `stretch` 会撑满整列。
`#早柚连接列表` 不带 `detail`，账号行没有收发计数，于是内容只占左边一小截，右边空掉一大片
玻璃底 —— 实测块宽 1224、内容只到 476，**右侧空 748px（61%）**。加 `self-start` 让它按
内容取宽，真机量到 1224 → 491（右空 5%）、样本 979 → 558。

**行内右侧那组要恒渲染，空了也占位。** 曾经给它加过「一个字都没有就不渲染」的判据，结果
同一块里有的行有右组、有的没有：连着的账号在连接列表页 `meta` 是空的、`status` 又是 1，
右组一个字都没有；而正在重连的那个有「已重连 N 次」。那些没有右组的行塌回内容宽，
**右缘跨度实测 325px**。恒渲染之后跨度 0px。

两条不冲突：空的右组宽度为 0，不会把块撑宽；块宽由最宽那行决定，`ml-auto` 只在块内分配
剩余空间。所以「块贴合内容」与「右缘对齐」同时成立 —— 恒渲染之后重量了一次，块宽仍是 558，
没有回涨。

### 卡内元素钉在标题行上，不居中

`Status.tsx` 的连接卡：序号块与右侧状态胶囊走 `self-start` + `mt-[-6px]` / `mt-[-3px]`，
不是 `self-center`。理由是卡高差得太多 —— 带子行的连接卡约 480px，只有名字和地址的
约 100px，差到 5 倍。`self-center` 会让序号漂在高卡的正中间，离它标注的那行标题两百多
像素。负 margin 是把它对到标题行的光学中线上（标题 38px × 1.2 = 45.6 行盒）。

### 图标一律用 lucide，不手绘

`Icons.tsx` 按语义名（`"status"` / `"changelog"`）映射到 `lucide-react` 组件，
`commands.ts` 只写语义名。换图标只动那张表。

**lucide 是描边图标**：`fill` 必须显式设成 `none`，否则浏览器按 SVG 默认的
`fill:black` 把每条开放路径首尾相连再填黑，图标糊成一团墨块。
`stroke-width 2` + round 连接是 lucide 的规范值，改了就和它的视觉重量不一致。

## 6. 页脚

四块**居中**排（`justify-content:center` + `gap 32px`），不是两端对齐：

```
[图标80] PLUGIN / 插件名   ✓STABLE / 版本号   │3×56   [图标80] POWER BY / 框架名 版本
                    时间戳  ·  MASTER 标记的指令仅主人可用
```

原型里用过 `flex:1` 的 spacer 把两半推到画布左右两端，中间空一大片 —— 那读起来是
三个孤岛而不是一行水印。

两张 logo 的**缩放方式不同**，这不是笔误：`logo.webp` 的字形只占画幅 70.7%，
img 溢出框 `112%` 把留白顶出去；`frame-logo.webp` 是满幅不透明图，内缩 8px。
这样两边字形都是约 63px。统一按同一种缩放，早柚那个会小三分之一。

一行放不下时靠 `--fs` 等比缩字号（`Footer` 里按 `textWidth` 预算），不换行 ——
换行会把「插件 × 框架」的并列关系拆断。

## 7. 体积与耗时 —— 量的时候别用预览的数字，也别只用样本数据

两个坑，都会让量出来的数字比真实出图小：

1. **`test/shot.mjs` 与 `test/preview.mjs` 走 `scale=1`，生产是 `SCALE=1.25`**（CSS zoom 打在
   `#container` 上，见 `styles/base.ts`）。像素数差 1.56 倍，体积差得更多。
2. **`test/fixtures.mjs` 是固定样本，比真实数据短且稀。** 帮助页样本 1800×3563，真机
   1800×5071 —— 高 1.42 倍，而且真实全套指令的文字更密（69.7 vs 60.8 KB/百万像素），
   两项相乘体积差 1.63 倍。样本量出 390 KB 的那张图，真机是 636 KB。

所以下面分两张表：**样本表**用来做 A/B（同一份数据比材质改动），**真机表**才是用户实际
收到的体积。页高随数据变，跨页比较要看 **KB/百万像素**（下称 KB/MP）这一列。

### 样本口径的 A/B，以及压花那一层曾经值多少钱

以下全部基于 `test/fixtures.mjs`（生产 scale 1.25 / jpeg q82 / 1800px 视口）。只用来比
材质，别当成真机体积：

| 页面     | `COOL`     | `LIGHT`    |
| -------- | ---------- | ---------- |
| `help`   | **390 KB** | **409 KB** |
| `status` | 360 KB     | 365 KB     |
| `list`   | 278 KB     | 278 KB     |

对照压花时代的同口径值（同样是样本，1800×3565）：

|                    | 体积        |
| ------------------ | ----------- |
| `COOL` 完整        | **2409 KB** |
| `COOL` 关掉高光层  | 527 KB      |
| `LIGHT` 完整       | 1419 KB     |
| `LIGHT` 关掉高光层 | 552 KB      |

所以 `help` 现在比「完整压花」省 84%（COOL）/ 71%（LIGHT），而且比当年「只关掉高光层」
那一档还要再省一档（390 vs 527、409 vs 552）。多出来的那一档不是滤镜省的，是**色斑
alpha 一起压低**换来的：色彩方差小，DCT 更好压。

顺带一个反转：从前 `COOL` 明显比 `LIGHT` 贵（2409 vs 1419），机理是它的基色 `#c6d0da`
落在中间调，`screen` 高光在那里能拉开最大明暗差、鳞片最清楚，而中间调加高频锐噪正好是
DCT 最压不动的组合。**那条机理随高光层一起没了** —— 现在两套三个页面的体积基本持平
（390/409、360/365、278/278），谁贵谁便宜已经不成一条规律。

### 卡面透出去多少，就要付多少体积 —— 这条待重测

卡片从实心面换成玻璃（§5），等于把原先被盖住的那片背景放回画面，它就要按背景的价钱
付钱。`test/probe-cardsize.mjs` 把每页的卡按回旧材质 A/B（生产 `scale 1.25` / q82，
同一进程连截，只差那串 class）：

| 页面         | 卡数 | 旧材质 | 玻璃  | 增量          |
| ------------ | ---- | ------ | ----- | ------------- |
| `list`       | 4    | 1059K  | 1200K | **+13.3%**    |
| `config`     | 8    | 1448K  | 1574K | +8.7%         |
| `changelog`  | 3    | 878K   | 933K  | +6.3%         |
| `list-empty` | 1    | 715K   | 773K  | +8.1%         |
| `help`       | 0    | 1911K  | 1911K | +0.0%（对照） |

（`COOL`；`LIGHT` 同向，`list` +15.2%）

**这批是压花时代量的，透出去的是鳞片 —— 待重测。** 那时背景是全页最贵的东西，所以把
它放回画面要付 13%；现在背景是低频渐变，本来就便宜（看上一节的绝对值），这几行的增量
大概率小得多，但没有实测就不写数字。

结构性的两条与材质无关，仍然成立：`help` 是对照组（只有 `Stats`，`+0.0%` 说明差值确实
只来自卡面）；增量不跟卡片个数走，跟**卡片盖住的面积**走 —— `config` 有 8 张卡却比
4 张卡的 `list` 便宜，因为设置行矮、连接卡带子行又高又宽。

要省体积只有 `quality` 一个旋钮（下面那节），别去压卡面的透明度 —— 那是把 §5 刚买到的
东西又退回去。

### 耗时不在纹理上，在色斑的模糊上 —— 而且只在 `--disable-gpu` 下

> 本小节的耗时数据全是压花时代量的，**结论与材质无关，原样保留**：那时页面上还有高光层，
> 而下面每一条比的都是「同一张页面开不开某个滤镜」，删掉高光只会让基线更低。
> 讲「纹理」的地方读作「当时那层压花高光」。

这一节曾经写着「开关高光的差值落在噪声里，整页 571 ms，日志里的 5922 ms 是冷启动」。
**那条结论是错的**，错因是量的时候没带本体的 launch 参数。

本体起 Chromium 带 `--disable-gpu`（`renderers/puppeteer/lib/puppeteer.js:31`），
光栅化全走 CPU。`test/shot.mjs` 那套只给 `--no-sandbox`，于是走了 GPU/SwiftShader，
CSS 模糊几乎免费 —— 两条路差了一个数量级。同一张 help（`COOL`、1.25、各 3 次中位数，
只计 `body.screenshot()`）：

| launch 参数                     | 色斑带 140~190px 模糊 | 不带模糊    |
| ------------------------------- | --------------------- | ----------- |
| **本体那套（`--disable-gpu`）** | 5288 ms               | **1335 ms** |
| 不带 `--disable-gpu`            | 353 ms                | 344 ms      |

所以：

- **色斑那五团模糊已经去掉**（§1①）。在生产的参数下它一个人占七成耗时，而画面
  逐像素平均只差 1.93/255。
- 高光纹理确实几乎不要钱（关掉整层只从 1445 ms 到 634 ms，且那 800 ms 里大部分是
  被省掉的 jpeg 编码量 —— 体积从 1888 KB 掉到 401 KB）。**纹理贵在体积，不贵在时间**，
  这半条结论仍然成立。
- 削高光层的 `rect`（6000 → 实际页高）、把它降到 1 octave，都**一点没省**
  （1445 → 1536 / 1548 ms）。Chromium 已经把滤镜按可见区域裁过了。

Node 侧（`buildCss` + SSR + 套骨架 + 落盘 + art-template）合计 **40 ms**，见
`test/bench.mjs`。

走本体渲染后端的端到端实测（`test/livecheck.mjs`，与 `#早柚帮助` 同一条路）：

```
改之前（日志，第 3/4 次，非冷启动）  5815ms / 5830ms   2673KB   COOL
改之后（COOL，连出三次）             2147 / 1856 / 1974ms      2704KB
```

真机（重启云崽后在群里发 `#早柚帮助`，`command.2026-08-21.log`）：

```
[05:25:50] [gscore-adapter-help][3次] 2673.15KB 5815ms   改之前
[07:11:56] [gscore-adapter-help][2次] 1513.41KB 2051ms   改之后
```

两条的体积差是 `COOL` 与 `LIGHT` 的差（05:25 是夜里、07:11 是白天），不是这次改动带来的
——改动本身让体积涨了约 1%（卡面透了，纹理透上来）。

> **别再拿「计数小就是冷启动」解释慢。** 那两条 5.8 秒的日志计数是 `[3次]` `[4次]`，
> 浏览器早热了。真正的原因是上面那张表。

> 还剩一个更大的旋钮，但它不在本插件里：把 `--disable-gpu` 从
> `renderers/puppeteer/config.yaml` 的 `args` 去掉。拿**生产那份 HTML**
> （`temp/html/gscore-adapter-html/help.html`，不是 fixture）在两套参数下各截 3 次：
>
> | launch 参数        | 截图（中位数） | jpeg    |
> | ------------------ | -------------- | ------- |
> | 带 `--disable-gpu` | 1638 ms        | 1513 KB |
> | 去掉               | **450 ms**     | 1506 KB |
>
> 画面逐像素比对：平均差 **0.82/255**、p99 **3**、超过 8 的只占 0.43%，且分布只落在
> 左右页边与 2px 分组竖线上 —— 是字形与细线的抗锯齿差异（两套光栅化器不同），不是
> 滤镜实现不同。裁出那一带两版并看分不出来。首次渲染要多付一次 GPU/着色器缓存预热
> （单次量到 1346 ms），之后才是 450 ms。
>
> 那是**本体级**改动，影响所有插件出图。**已决定先不动** —— 1900~2050ms 够用，
> 而 `--disable-gpu` 本来就是为无头稳定性加的，换来 1.2 秒去赌显卡驱动在无头下不
> 抽风不划算（真抽风时坏掉的是所有插件的出图，不只本插件）。
>
> 若哪天真要动：从插件里 hook 渲染器实例的 `config.args` 比改本体的 config.yaml
> 更好版本化，但**副作用一样是全局的**（渲染器是共享单例），而且藏在插件里更难查
> —— 真要动就明着改本体配置。

### 省体积：唯一不动观感的旋钮是 `quality`

**下面这张表整张都是压花时代量的，待重测。** 新材质只有 82 这一档有实测值（本节开头
那张表：278~409 KB），其余三档没有量过，别拿这里的 KB 数当现在的值：

|                | `COOL`      | `LIGHT`     |
| -------------- | ----------- | ----------- |
| 88             | 2409 KB     | 1419 KB     |
| **82（当前）** | **1877 KB** | **1063 KB** |
| 76             | 1533 KB     | 858 KB      |
| 70             | 1320 KB     | 738 KB      |

停在 82 的理由也换了。原来是「JPEG 的块效应正好被高频纹理盖住，76 起细鳞片开始被抹平，
那是在削这版设计要的东西」—— 鳞片没了，这条不成立。现在的理由是**没有动机**：一张图
278~409 KB，离任何限额都远，再省几十 KB 换不到东西；而 82 是上面那批体积数字的量取
口径，往下调得连着把整批重测一遍。

### 试过的其他改法，全部否掉

压花时代在纹理那一侧试过的，连同那层高光一起作废了 —— 留着只为别再走一遍
（KB 数都是压花时代的量）：

```
bf 0.1→0.05 + blur 0.85   鳞片被拉成脑珊瑚那样的虫状纹
bf 0.1→0.07 + blur 0.55   介于两者之间，仍偏糊
numOctaves 2→1            细节层没了，只剩一层大波浪
COOL 色斑 alpha 降一档     只省 22 KB，没意义
gloss opacity .85→.45     能到 1715 KB，但纹理明显发闷
SCALE 1.25→1.0            能到 1627 KB，代价是 QQ 里放大看文字会糊
```

最后一条与材质无关，结论仍然作数：**`SCALE` 不降**，QQ 里放大看文字会糊。
第四条现在算是被实践推翻了 —— 色斑 alpha 确实降了一档，只不过动机不是省体积，而是补上
高光层撤走后暗部丢掉的那点提亮（§1① / §2 末），省下的体积是白捡的。

不让步的东西换了一个：压花时代是「鳞片必须锐，糊了就是磨砂玻璃」；现在是**絮状调制必须
留在低频、而且必须看不出来** —— `baseFrequency` 往上抬就回到和笔画抢像素的老问题，
`opacity` 往上抬就回到第一代那张「有噪点的渐变图」。要省体积仍然只让 `quality`。

## 8. 硬约束（改任何一条前先读）

1. **改色斑 alpha、暗角、`filter#fl` 任一参数之后必须跑 `test/inkprobe.mjs`，或至少看
   截图。** `contrast.mjs` 只算平底，抓不到背景暗部咬花正文。高光层删掉之后暗部没有
   `screen` 那点提亮兜着，`COOL` 的 `muted` 只剩 4.92:1（余量 0.42），比压花时代更吃紧
   （§2 末）。
2. **不要把任一套的 `bg` 改回深色。** 理由不再是「深底上 `screen` 高光是一屏雪花」——
   高光层没了。现在的理由是：色斑是半透明叠色，在近黑上几乎不产生色差，而它是画面唯一
   的主体，下面再没有纹理兜底；而且全套角色色 / `muted` / `spectrum` 都是照两个亮基色
   实测配出来的，换底等于要重配一整套（§2）。
3. **mask 与它的使用者同一个 `<svg>`。** 跨 svg 引用 mask 会静默失效。现在背景层里已经
   没有 mask（§1 末），这条留给下次要加的人。
4. **`rotate` 与 `primary/secondary/accent` 同值。** `contrast.mjs` 有断言。
5. **字体栈两处拷贝同步改。** `theme.ts` 与 `tailwind.css` 的 `@theme`。
6. **lucide 图标 `fill:none`。** 否则糊成墨块。
7. **色斑 alpha 别抬回压花时代那一档。** 当前最浓一团是 `COOL` `.26` / `LIGHT` `.22`
   （旧上限 `.34`）。斑越浓，落在斑上那部分字与 `contrast.mjs` 算出来的值偏离越大，
   而现在没有高光层给暗部兜底（约束 1）。
8. **卡面取值只有 `Layout.tsx` 的 `GLASS` 一份，五处都引它。** 别把那串取值抄到调用处
   —— 抄一遍就会漏改一处，而 `classes.test.mjs` 查不出「材质不一致」（§5 末）。
   也别把它挪出 `components/*.tsx`：Tailwind 只扫这个 glob，挪走会静默丢掉这几条规则。
   改完跑 `test/probe-cardface.mjs` 核透出率与卡上正文的对比度。
9. 改完跑 `pnpm build && pnpm test`，再 `node --import tsx test/preview.mjs`
   看四个页面的两套调色板。`test/inkprobe.mjs` 核正文在真实像素上的对比度，
   `test/glassink.mjs` 核统计卡卡面，`test/probe-cardface.mjs` 核其余四处卡面，
   `test/bench.mjs` 核 Node 侧耗时。
10. **核体积别用 `test/shot.mjs` 的数字。** 它走 `scale=1`，生产是 `1.25`，
    像素差 1.56 倍（见 §7 开头）。要准就给 `#container` 打上 `zoom:1.25` 再截
    （`test/probe-cardsize.mjs` 就是这么量卡面那笔体积的）。
11. **核耗时必须带上本体的 launch 参数。** 少一个 `--disable-gpu`，CSS 模糊这类
    滤镜就从 5 秒变成免费，量出来的数字和生产没有任何关系（§7 那张表就是为此存在的）。
    最省事的办法是走 `test/livecheck.mjs`，它直接调本体的渲染后端。
12. **色斑那五团别再加回 CSS 模糊。** 它在生产参数下占七成耗时，而画面逐像素
    平均只差 1.93/255（§1① / §7）。想要更柔的边就调渐变的收尾百分比，不要加滤镜。
13. **`Help.tsx` 的分组竖线别加回来。** 归组靠缩进（`pl-[34px]` / `pl-[30px]`），
    竖线是另一种框（§5）。左下角那块 45° 斜纹同理，它已换成一团柔光（§1）。
14. **开关别退回「点 + 开启/关闭 文字」的胶囊。** 96×52 轨道 + 40px 滑块，状态靠
    「填色 + 滑块位置」两个通道；原来那条「轨道要 60px、并排放文字会撑到三分之一页宽」
    的顾虑随文字一起没了 —— 现在 96px 比带字的胶囊（约 123px）还窄（§5）。
15. **改动结果条别退回语义色描边 + 语义色底 + 6px 左粗边。** 卡面走全页唯一那种
    `GLASS`，语义色只落在 52px 图标方块与失败行的文字上（§5 / §3 末）。
16. **连接卡别把账号拆回「bind 胶囊排 + runtime 子行」两块。** 那是同一份账号的两遍
    平行枚举，账号号码会出现三次、心跳与收发计数各三次（§5「同一份东西只枚举一遍」）。
    往账号行里加字段前先问一句：这个值是不是已经在同一张卡的别处说过了。
