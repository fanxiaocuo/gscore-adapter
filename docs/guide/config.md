# 配置

这一页帮你做到三件事：改对那几项真正常用的配置、让多个机器人号接进同一个核心、让大图大文件发得出去。

## 三个入口，改哪个都一样

| 入口 | 怎么用 | 适合 |
| :--- | :--- | :--- |
| 指令 | 发 `#早柚设置` 出图列出全部可改项与改法，见[指令](./commands.md) | 手机上随手改 |
| 网页面板 | 装了 QQBot-Web-Adapter 或[锅巴](https://github.com/guoba-yunzai/guoba-plugin)后，控制台多一页，见[面板](./panel.md) | 要顺便看实时状态 |
| 配置文件 | 改插件目录下的 `config/config.yaml` | 批量改、想写注释 |

三个入口改完都即时生效，不用重启云崽（只有心跳那两项会顺带重连一次），yaml 里已有的注释也不会丢。

::: tip 改 config/config.yaml，别改 resources/config/default_config.yaml
后者是出厂默认值，插件升级会覆盖它。首次运行会把它复制成 `config/config.yaml` —— 你只写想改的项就行，没写的自动继承默认值。

插件升级后新增的配置项，启动时会连注释一起追加到你的 `config.yaml`，已有的项一律不动（包括你写的连接地址）；插件第一次动你这份文件之前会留一份 `config.yaml.bak`。
:::

## 大多数人只会改这几项

| 你想做什么 | 改哪一项 | 最省事的改法 |
| :--- | :--- | :--- |
| 换核心的地址 / 端口 | 连接的 `url` | `#早柚修改连接 1 url=192.168.1.5:8765` |
| 让另一个机器人号也接进这个核心 | 连接的 `bind` | 在那个号上发 `#早柚添加连接 <同一个地址>` |
| 暂时不连核心 | `enable` | `#早柚设置适配器关闭` |
| 只让群消息进核心 | `filter.report_private` | `#早柚设置私聊上报关闭` |
| 别让核心抢某几条指令 | `filter.block_prefix` | [面板](./panel.md)「过滤」页的「屏蔽前缀」 |
| 大图发不出去 | `media_max_size` | `#早柚设置最大媒体大小 20` |

剩下的项，多数人一辈子不用动。

## 手写配置：最小的一份

不想发指令的话，`config/config.yaml` 写成这样就够：

```yaml
enable: true
client:
  enable_ws: true
  connections:
    - name: gsuid_core
      url: ws://127.0.0.1:8765     # 只写到 host:port，别带 /ws/... 路径
      token: ""
      enable: true                 # 出厂那条示例是 false，记得改成 true
      bind: ["2463381624"]         # 要接入核心的机器人账号，至少填一个
```

两处最容易错：

- `url` 只写核心地址（`host:port`）。路径不用你写，理由见[多个账号接同一个核心](#多个账号接同一个核心)
- `bind` 至少一个账号。空着的话这条连接启动时会被跳过，日志写「连接 gsuid_core 没有可用的绑定账号，已跳过」

## 一条连接有哪些字段

| 字段 | 说明 | 默认 |
| :--- | :--- | :--- |
| `name` | 连接名。日志、指令定位、状态图上显示的都是它 | `gsuid_core` |
| `url` | 核心地址，只到 `host:port` | `ws://127.0.0.1:8765` |
| `token` | 核心以 `?token=` 接收，留空则不发送 | 空 |
| `enable` | 这条连接是否启用 | 出厂那条示例是 `false` |
| `reconnect_interval` | 重连间隔（秒），最小 `1` | `5` |
| `max_reconnect_attempts` | 最大重连次数，`0` 或负数为一直重连 | `5` |
| `bind` | 接入这个核心的机器人账号，至少一个 | 空 |
| `exclude` | 不让这些账号走这条连接，比 `bind` 优先 | 空 |

`token` 写在字段里。写成 `ws://host:8765/?token=abc` 内联进地址也认（插件会把它摘出来当凭据，日志、面板与状态图上都不带查询串），只是以后手改地址那行时容易把凭据一起改掉。

`bind` / `exclude` 不必手改文件：`#早柚修改连接 1 bind+=<账号>` 与[面板](./panel.md)的账号开关都能增删。同一个账号两边都写了的话，那个号不会连，日志说一句「按 exclude 处理」。

重连是逐次加倍的：从 `reconnect_interval` 起步，每次翻倍，封顶它的 12 倍。默认 5 次约覆盖 2.3 分钟 —— 核心重启够用，而地址写错时不会整夜刷日志。次数用尽后发 `#早柚重连` 恢复；想一直重连把 `max_reconnect_attempts` 写 `0`。

指令与面板都不收小于 1 的 `reconnect_interval`：0 秒重连是紧密循环，断线时会把 CPU 与对端一起灼掉。手改文件写 `0` 运行时按 5 秒起步，但**负数会原样生效**（退避算出负延时，`setTimeout` 立刻回调），所以别手写负值。

## 多个账号接同一个核心

配置里存的是核心地址，`/ws/Yunzai-<账号>` 那段路径由插件在连接时按 `bind` 里的每个账号自己拼，不写进配置文件。

为什么：核心是按**路径**认客户端的。两个机器人号共用同一条路径，核心就当成同一个客户端重连了，后连上的把先连上的顶下去 —— 两个号轮流掉线。一个账号一条路径就各自独立。

所以配置里的一条连接，跑起来是 N 条：

```
配置 1 条                      实际 3 条
─────────────────────────      ────────────────────────────────────
url:  ws://127.0.0.1:8765      ws://127.0.0.1:8765/ws/Yunzai-账号A
bind: [账号A, 账号B, 账号C]  →   ws://127.0.0.1:8765/ws/Yunzai-账号B
                               ws://127.0.0.1:8765/ws/Yunzai-账号C
```

看得见的差别：

- `#早柚状态` 与面板上，一条配置是一张卡片。卡片上的状态是合起来看的（任一账号连上就算这个核心通了），下面按账号列出每个号自己的状态
- 停起可以按账号来：[面板](./panel.md)上关掉某个账号的开关，只断那个号那一条，同一个核心上别的号不受影响
- 两条连接算出同一条路径时（比如两条都绑了同一个账号），保留先出现的那条，日志与面板上会写明跳过了谁

<details>
<summary>地址里写了路径会怎样（一般用不到）</summary>

`url` 里带了路径（如 `ws://127.0.0.1:8765/ws/MyBot`）时，插件**不动它**：只起一条 ws，路径原样发给核心。面板上把这种连接叫「兼容连接」，把只填 `host:port` 的那种叫「自动连接」。

两种连接的语义完全不同，别混着理解：

| | 只填 `host:port` | 地址里写了路径 |
| :--- | :--- | :--- |
| ws 条数 | 每个绑定账号一条 | 恒为一条 |
| 路径 | 自动生成 `/ws/Yunzai-<账号>` | 你写的那一段，原样 |
| `bind` 的作用 | 决定生成哪几条连接 | 只是转发白名单，**不影响路径** |
| `bind` 留空 | 起不来，报错并跳过 | 合法，等于不限账号 |

::: warning `bind` 留空在两种连接上的后果相反
写了路径 + 空 `bind` 是「不限账号」而不是「不转发」—— 这条 ws 会把所有机器人的消息都送进这个核心。想只转发某几个号就把它们写进 `bind`，但仍然只有一条 ws，核心侧看到的是同一个客户端。
:::

把路径显式写成 `/ws/Yunzai` 而又没绑账号时，日志会提醒你这是条共享路径、多个机器人会互相顶掉。

</details>

## 谁的消息进核心

```yaml
filter:
  report_private: true    # 私聊消息
  report_group: true      # 群消息（QQ 频道也算群）
  report_meta: true       # 进群 / 退群 / 戳一戳
  only_reply_at: false    # 群里只有被 @ 或带前缀才上报
  prefix: ["#", "*"]      # only_reply_at 开着时，以这些开头也算触发
  block_prefix: []        # 以任一项开头就不上报，用来把某几条指令留给本地插件
  block_include: []       # 出现任一项就不上报
  white_group: []         # 只上报这些群，留空为全部
  black_group: []         # 这些群不上报
  black_user: []          # 这些人不上报
```

三个 `report_*` 是最粗的一刀，默认全开。想「只让群消息过核心」不必把私聊用户逐个列进 `black_user`；核心侧没装吃「进群 / 退群 / 戳一戳」的插件时，关掉 `report_meta` 能省下全部无用上报。

群和用户的黑白名单同时管消息和这三类事件；`only_reply_at` / `block_prefix` / `block_include` 看的是文本，只管消息。名单在[面板](./panel.md)的「过滤」页也能改，群号和好友还能从列表里挑。

## 大小与有效期这三项

| 项 | 管什么 | 默认 |
| :--- | :--- | :--- |
| `media_max_size` | 图片 / 语音 / 视频超过这个大小就改用外链发，不再塞 base64 | 10 MB |
| `file_max_size` | 文件段只能内联 base64（协议里没有 URL 形式），超过这个大小直接不发 | 50 MB |
| `link_expire` | 外链多久失效，也是内置文件服务留着这份内容的时长 | 300 秒 |

::: warning 面板和指令按 MB / 秒填，配置文件里存的是字节 / 毫秒
[面板](./panel.md)、锅巴、`#早柚设置最大媒体大小 2` 这三个入口一律按 **MB / 秒** 填，换算在存盘时做。MB 按 1024² 算：填 `2` 落盘是 `2097152`，填 `10` 是 `10485760`；`link_expire` 填 `300` 落盘是 `300000`。

手写 yaml 时按字节 / 毫秒写。`#早柚设置 media_max_size=2097152` 是另一种写法，直接收字节，与 `最大媒体大小 2` 等价。
:::

两个大小上限最多 **256 MB**（面板下限 0.01 MB，`#早柚设置` 的下限是 1 KB）。调过头等于关掉外链兜底，每个附件都要在内存里 base64 一份。`file_max_size` 与 `link_expire` 没有中文指令，只能在面板或配置文件里改。

## 大图发不出去怎么办

超过 `media_max_size` 的图片 / 语音 / 视频塞不进 base64，得给核心一个 http 外链让它自己来拉。插件按下面的顺序找一个能生成外链的东西 —— 看的是框架**有没有这个能力**，不是看框架叫什么名字：

```
框架自带的文件服务（Bot.fileToUrl）→ 插件内置文件服务 → upload_hook 图床 → 放弃这一段并打日志
```

TRSS-Yunzai 有 `Bot.fileToUrl`，走第一条就完了，底下这些都不用管。Miao-Yunzai 没有，插件会自己起一个内置文件服务顶上，默认开启、不用配置：

- 内容只存在内存里，`link_expire` 到期自动清，不落盘
- 链接路径是一段随机 token，猜不出来；核心取走即删（`once: true`）
- 端口只在真要发外链时才开。例外：框架没有自带 web 服务、而你又把 `port` 固定成了非 0 时，启动就会开 —— 那是[图床转接口](#让核心的图走本机图床)要用它
- 外链里的 host 优先用 `public_host`；留空则取 ws 连接的本机地址（核心在 Docker 或另一台机器上时，写死 `127.0.0.1` 会让它连到自己身上）

```yaml
file_server:
  enable: true      # 关掉则回落到 upload_hook
  port: 0           # 0 = 每次随机取可用端口
  host: 0.0.0.0     # 核心常在 Docker / 另一台机器，只听 127.0.0.1 它连不进来
  public_host: ""   # 留空自动推断；推断不对时在这写死云崽的可达地址
  once: true        # 取走即删；核心侧会重复拉同一个链接时改成 false
```

::: tip 文件段没有这条兜底
`file` 段只能内联，超过 `file_max_size` 就直接跳过，日志写「file 段 X.X MB 超过上限 Y.Y MB，已跳过」。要发大文件只能把 `file_max_size` 调大，代价是内存。
:::

`upload_hook` 是内置服务的后备（服务被关掉、或端口起不来时才用；内网穿透场景下图床给的是公网地址，比内置服务可靠）。它指向一个模块，默认导出一个上传函数：

```js
// 相对云崽根目录或绝对路径，如 plugins/gscore-adapter/my-upload.js
export default async (buf, name) => "https://图床地址/xxx.png"
```

返回 http(s) 链接算成功；返回空或抛错就跳过这一段并打日志。实在不想折腾，把 `media_max_size` 调大让大图走 base64 也行（上限 256 MB，代价是内存占用与单帧体积）。

## 让核心的图走本机图床

**只有 QQ 官方机器人（QQBot）用户可能需要这一节**，而且是核心那边把「图片发送方式」配成了链接的时候。

核心给官方机器人这类平台发「图片 + 按钮」时会把图文压成一段 markdown，而那一步要求核心自己先把图片变成公网 URL —— 核心会把图传给它配置里的「自定义图床 API」。麻烦在于 ImageBed-Plugin 那类图床插件只提供进程内的 `Bot.imageToUrl()`，而核心是独立的 Python 进程，调不到。

所以本插件挂了一个转接口，把 `imageToUrl` 包成核心要的响应形状。在核心的 `pic_upload_config.json` 里填：

| 字段 | 值 |
| :--- | :--- |
| `PicUploader` | `custom` |
| `custom_url` | `http://127.0.0.1:2536/gscore/imagebed` |
| `custom_header` | `{}` |

启动日志里会直接写出该填的那个地址（端口按你框架实际用的那个算），照抄即可。

::: warning custom_header 必须写 `{}`，不能留空串
留空串会让核心在加载阶段就抛 `JSONDecodeError`。另外 `pic_upload_config.json` 这几项改完必须**重启核心**，热重载不管用。
:::

::: tip 端口从哪来
这个接口优先挂到云崽本体已经在跑的那个 web 端口上（默认 2536），所以它跟 `file_server.port` 无关，`port: 0` 也不影响。只有 Miao 那种没有本体 web 服务的框架才回落到内置文件服务，那时必须把 `file_server.port` 固定成一个具体端口 —— 随机端口和写死的 `custom_url` 天生对不上。
:::

访问控制：**本机来源（`127.0.0.1`）不用凭据**。核心跨机（Docker / 另一台机器）时才要给 `file_server.imagebed_token` 配个口令，并把地址写成 `…/gscore/imagebed?token=<口令>`；不配口令时非本机来源一律拒绝。放在反向代理后面时**必须**配口令 —— 判来源只看连接对端地址，不认 `X-Forwarded-For` 这类能伪造的请求头。

<details>
<summary>不想用这个转接口</summary>

核心那边把 `EnablePicSrv` 关掉，图就原样以 base64 发过来，公网化交给平台适配器自己做（QQBot-Plugin 收到图会调 `Bot.imageToUrl`，icqq 直传，本来就不需要公网地址）。少一次上传往返，代价是 ws 帧里带着 base64。

别留着 `EnablePicSrv: true` + `PicUploader: local` + `PicSrv: ""` 这个组合：核心拼出来的地址主机名是空的（`link:///api/image/xxx.jpg`），图永远加载不出来。

</details>

## 平台标识 bot_id_map

核心用 `bot_id` 区分平台（`onebot` / `qqgroup` / `qqguild` / `kook` …）。这张表把云崽这边的适配器映射成核心认识的那个名字，只能在配置文件里改（面板上没有它）。

```yaml
bot_id_map:
  QQ: onebot          # 适配器 id，粗粒度，一个键覆盖多家
  QQBot: qqgroup
  ICQQ: onebot        # 适配器名字，精确到某一家
  QQGuild: qqguild    # 频道单独判
  default: onebot     # 都没命中时的兜底
```

一般不用动它：`#早柚添加连接` 和面板的账号开关都会把推断出的平台标识按账号写进这张表，`#早柚状态` 与面板上看得到结果（推断不出时显示「未识别」，不会拿默认值糊弄你）。

核心侧插件没反应、怀疑平台认错了的话，加一行 `<账号>: <平台标识>`（账号精确匹配优先级最高），或者发 `#早柚修改连接 1 id=qqgroup`。

<details>
<summary>为什么 id 和名字都要查</summary>

查找顺序：账号精确匹配 > 频道 > 适配器 id > 适配器名字 > 按账号形状猜 > `default`。

ICQQ / OneBotv11 / OPQBot 三家的适配器 id 全是 `QQ`，只查 id 分不开它们；而只查名字的话，`QQ` 这种粗粒度的键写了没用。所以两者都查。

QQBot-Plugin 用同一个适配器同时处理 QQ 群和 QQ 频道，按适配器查表也分不开，所以频道按事件形状单独判（群号带 `qg_` 前缀）。

查表全落空之后还有一层：按账号前缀（`qg_` / `wx_` / `tg_` / `dc_` / `mv_` / `ko_`）和 QQBot appid 的形状再猜一次。非 QQ 平台的账号在默认表里根本没有键，只靠 `default` 会全部兜成 `onebot`，核心侧收到的平台就是错的。

</details>

## 其余零碎项

| 项 | 说明 | 默认 |
| :--- | :--- | :--- |
| `enable` | 总开关。关掉立刻断开全部连接，打开立刻重连 | `true` |
| `client.enable_ws` | 关掉则一条 ws 都不建（适配器本身还在） | `true` |
| `client.heartbeat` | ws ping 间隔（秒），0 关闭。改完会重连一次 | `30` |
| `client.heartbeat_timeout` | 这么久没收到回应就判掉线重连（秒），0 关闭 | `90` |
| `log_truncate` | 日志里把 base64 长串截断 | `true` |
| `notify_master` | 连接断开与恢复时私聊主人（`[早柚核心] xxx 已断开` / `xxx 重连成功`）。核心常重启的话会比较吵 | `false` |

## 定时检查更新

```yaml
update_check:
  enable: false     # 关掉后 #早柚检查更新 仍能手动用
  interval: 180     # 检查间隔（分钟），低于 30 按 30 算
  delay: 5          # 启动后多久做第一次检查（分钟），错开启动高峰
  notify: true      # 发现新版本时私聊主人
```

只做检查与通知，不会自动更新 —— 更新仍要发 `#早柚更新`。改完即时生效。
