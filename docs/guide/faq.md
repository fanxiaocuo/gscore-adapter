# 常见问题

按现象分类。日志里的关键字通常已经指明了是哪一环出问题。

## 连不上，日志刷「连接错误」

检查核心是否在跑、地址端口是否正确、`token` 是否匹配。地址只写到 `host:port`，路径由插件按绑定账号生成，不用也不该自己写。容器部署时别把地址写成容器内的 `127.0.0.1`。

日志与面板上还有一类「压根没起来」：地址解析不了、这条连接没有绑定账号、或者两条连接算出了同一条路径。这些在启动那一刻就报了，连接卡片只会显示「未启动」——原因去 [Web 面板](./panel.md)顶部那条「有连接没能启动」里看。

## 为什么配置里看不到 /ws/Yunzai 了

因为它现在是运行时才拼出来的。配置里只存核心地址（`host:port`）和 `bind` 账号列表，建连时按每个绑定账号生成 `/ws/Yunzai-<账号>`，一个账号一条 ws。

`#早柚状态`、面板的运行时子行、核心后台都能看到这些路径；配置文件里则不该出现，写了反而会被当成[自定义路径](./config.md)按另一套语义处理。

## 两个账号连同一个核心，为什么以前会互相顶掉

核心 `core.py` 的入站路由是 `@app.websocket("/ws/{bot_id}")`——**路径就是客户端在核心侧的身份**。两个云崽账号共用 `/ws/Yunzai` 时，核心认为是同一个客户端重连了，于是后连上的把先连上的挤下去，两个号轮流掉线。

现在一个账号一条路径（`/ws/Yunzai-<账号>`），互不干扰。所以只填 `host:port` 的连接必须至少绑一个账号：没有账号就拼不出路径，这条连接也就不存在。

反过来，写了自定义路径的连接**永远只有一条 ws**：多个账号共享它，在核心侧是同一个客户端。要真正分开，还是回到「只填 `host:port` + 绑定账号」。

## 连上了但核心没反应

核心侧看是否收到消息。若消息到了但插件没触发，多半是平台标识不对——核心用 `bot_id` 区分平台，给该账号在 `bot_id_map` 里单独写一行，或发 `#早柚修改连接 1 id=qqgroup`。

也检查一下这个号是不是真的绑在这条连接上：`#早柚连接列表` 出图时绑定账号显示为头像胶囊，面板上点开绑定区能逐个看。账号同时写进 `bind` 与 `exclude` 时不会转发（`exclude` 优先级更高），面板会在那一行标红说明。

## 每条消息被处理两次

同一条消息被两个早柚核心适配器上报了。检查是否还装着框架自带的 `plugins/adapter/GSUIDCore.js` 或其他核心适配器（如 ws-plugin 的相关功能），只留一个。也可能是同一个核心配了多条连接，用 `#早柚连接列表` 查。

## 图片发不出去 / 核心拿到占位图

先看外链是谁发的。TRSS 走 `cfg.server.url`，核心在 Docker 里而它指向 `127.0.0.1` 就拉不到，改成核心可达的地址。

Miao 走内置文件服务，正常会自动取 ws 连接的出口地址；若跨网段 / 跨容器导致推断不对，用 `file_server.public_host` 写死云崽的可达地址，并确认 `file_server.host` 不是 `127.0.0.1`。日志里「内置文件服务启动失败」多半是端口被占，`port: 0` 交给系统分配即可。

实在不想折腾就调大 `media_max_size` 让图片走 base64 内联，上限 256 MiB。

## 撤回功能突然失效

核心连续 3 次拿不到 `recall_message_id` 就会永久关掉撤回。重启核心恢复。若反复出现，说明当前适配器的 `sendMsg` 返回值里取不到 message_id。

## QQBot 上本该出图，却什么都没收到

核心向 QQ 官方机器人这类平台发「图片 + 按钮」时会把图文压成一段 markdown，而那一步取图片链接的前提是核心自己已经把图片转成了外链。核心的「图片发送方式」选了 link 却没配图床时，转链接那步落空，图片既没写进 markdown 也没留在消息里，被核心静默丢掉——纯图片的响应（比如某些插件的帮助图）到适配器手上就只剩一个空 markdown 加一组按钮。

**这是核心侧的配置问题，改核心的图片发送方式或补上图床即可**，适配器补不回那张图（它压根没离开核心）。插件这边只做两件事：空 markdown 不再往下发（对用户没有信息量，QQ 侧还可能因空内容报错顺带把按钮也拖没），并打一条 warn 指向核心的图片配置——不然现象只是「帮助没图了」，不给线索就得去翻核心源码。

## 按钮 / markdown 发出去没了

不是每个适配器都发得出这些段，而核心不知道下游是什么平台、会按 onebot 一律照发。Milky / OneBotv11 的 `makeMsg` 没有 button / markdown 分支，OPQBot 连 `video` / `file` / `reply` 都直接跳过。

本插件**不做降级**：适配器本来就会丢弃它们，再加一层「转成文本」只是用噪音替换静默丢弃，内容并没有真的送达。按钮目前基本只有 QQBot 在用，而 QQBot 原生支持。要按钮就用支持按钮的适配器。
